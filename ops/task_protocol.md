# AXIS — Task Protocol

## Task Lifecycle

```
Created → Assigned → In Progress → [Blocked] → Done / Cancelled
```

There is no "someday." Every task has a status and a due date.

---

## Task Structure

Every task must have:

```
Title: [verb + noun — e.g., "File LLC paperwork in Texas"]
Owner: AXIS or Morris
Due: [specific date]
Status: Not Started / In Progress / Blocked / Done / Cancelled
Priority: P1 (this week) / P2 (this month) / P3 (backlog)
Blocker: [if blocked — exactly what is needed]
Notes: [any context, links, or references]
```

---

## AXIS Responsibility on Tasks

- AXIS creates tasks proactively when work is identified — doesn't wait to be asked
- AXIS updates task status after every action taken
- AXIS never marks a task Done unless it is actually done — not "sent," not "drafted," done
- If a task is blocked >24h, AXIS escalates
- If a task has been open >72h with no movement, AXIS surfaces it in the daily brief

---

## Morris's Responsibility

- Review daily brief and unblock AXIS where needed
- Make decisions within 48h — after that AXIS escalates
- Mark tasks as Cancelled if they're no longer relevant (don't leave them rotting)

---

## Closure Criteria

A task is Done when:
- The intended outcome exists in the real world (not just in a draft or plan)
- AXIS has confirmed it
- Any follow-on tasks have been created

---

## Weekly Task Review (Every Monday)

AXIS surfaces:
1. All tasks completed last week
2. All tasks overdue
3. Top P1 tasks for the coming week
4. Any zombie tasks (open >2 weeks with no movement) — force a close/cancel decision
